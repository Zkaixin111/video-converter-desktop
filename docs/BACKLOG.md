## P1（下一个迭代，直接影响可用性）

| 编号 | 项 | 现状 | 为什么放 P1 |
|---|---|---|---|
| P1-01 | ~~**批量队列**~~ | ✅ 已实现（P1）：拖拽 / 多选入队、共用全局参数 or 单任务独立参数、失败继续 or 暂停、失败可重试删除；转换页可整批组装（逐个加 or 一次多选，同批统一格式，上限 10 个） | 单并发 FIFO + 入队即预定输出路径；队列持久化仍不做（重启不恢复），见 P2-06 |
| P1-02 | ~~**转换历史**~~ | ✅ 已实现（P1）：`userData/history.json`，队列页最近记录区 | 依赖 P1-01 的任务表这一判断已被证伪——历史与调度解耦后可以独立落地 |
| P1-03 | ~~**参数预设真正生效**~~ | ✅ 已实现（P1）：三档 → CRF/码率/音频码率，`standard` 与 MVP 一致 | 「画质档位 → 参数」的映射进了 planner，并补了单测 + 一条真转两次的集成测试 |
| P1-04 | **硬件加速编码**（NVENC / QSV / AMF） | 设置页置灰 | 需要探测可用加速器 + 回退策略；失败时的错误信息与软编完全不同 |
| P1-05 | **字幕与多音轨保留** | 明确丢弃并提示 | 需要容器能力矩阵扩展（MKV 支持、MP4 不支持）+ 轨道选择 UI |
| P1-06 | **输出质量校验**（SSIM / 抽样解码） | 只做容器级校验 | 「能播」和「画质没崩」是两件事；SSIM 需要额外解码一遍，耗时翻倍 |
| P1-07 | **分辨率缩放 / 裁剪** | 无 | 手机视频导不进去的场景里，分辨率是第二大类原因 |
| P1-08 | **断点续传 / 段级重试** | 队列已支持「整条任务重试」，但没有断点续传 | 断点续传需要 segment 级转码 + 拼接，属于架构改动；整条重试已能覆盖绝大多数场景 |

## 不做（明确排除）

- **上传/云端转码**：产品定位就是「文件不出本机」，这是与在线转换站的核心差异。
- **DRM / 加密内容处理**：合规红线。
- **屏幕录制、剪辑、压制预设分享**：不在「格式转换」的问题域里。

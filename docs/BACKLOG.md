# BACKLOG —— MVP 之后要做什么

本文件是「有意没做」的清单，不是「忘了做」的清单。
代码里对应的位置都留有 `P1` / `P2` 标记，两侧能对上。

## P1（下一个迭代，直接影响可用性）

| 编号 | 项 | 现状 | 为什么放 P1 |
|---|---|---|---|
| P1-01 | **批量队列** | 单任务，第二份文件会提示「请先更换」 | 需求里出现频次最高的诉求；需要任务表 + 并发上限 + 队列持久化，工作量约等于当前 JobManager 的两倍。**待先确认交互（ROADMAP §5）** |
| P1-02 | ~~**转换历史**~~ | ✅ 已实现（P1）：`userData/history.json`，队列页最近记录区 | 依赖 P1-01 的任务表这一判断已被证伪——历史与调度解耦后可以独立落地 |
| P1-03 | ~~**参数预设真正生效**~~ | ✅ 已实现（P1）：三档 → CRF/码率/音频码率，`standard` 与 MVP 一致 | 「画质档位 → 参数」的映射进了 planner，并补了单测 + 一条真转两次的集成测试 |
| P1-04 | **硬件加速编码**（NVENC / QSV / AMF） | 设置页置灰 | 需要探测可用加速器 + 回退策略；失败时的错误信息与软编完全不同 |
| P1-05 | **字幕与多音轨保留** | 明确丢弃并提示 | 需要容器能力矩阵扩展（MKV 支持、MP4 不支持）+ 轨道选择 UI |
| P1-06 | **输出质量校验**（SSIM / 抽样解码） | 只做容器级校验 | 「能播」和「画质没崩」是两件事；SSIM 需要额外解码一遍，耗时翻倍 |
| P1-07 | **分辨率缩放 / 裁剪** | 无 | 手机视频导不进去的场景里，分辨率是第二大类原因 |
| P1-08 | **断点续传 / 失败重试** | 无（失败卡不提供重试按钮） | 需要 segment 级转码 + 拼接，属于架构改动 |

## P2（锦上添花）

| 编号 | 项 | 备注 |
|---|---|---|
| P2-01 | 深色模式 | 设计 Token 已预埋，只差 `prefers-color-scheme` + `[data-theme]` 两套变量 |
| P2-02 | 拖入多个文件自动排队 | 依赖 P1-01 |
| P2-03 | 输出体积上限（目标大小模式） | 双遍编码 |
| P2-04 | 转换前后对比预览（抽帧对照） | 需要内嵌播放器或图片对比组件 |
| P2-05 | 系统托盘 + 最小化到托盘继续转码 | 关窗即退出目前是有意的 |
| P2-06 | 崩溃恢复（未完成任务标记为「意外中断」） | 依赖 P1-01 的持久化 |
| P2-07 | 多语言（英文） | 现有文案全部硬编码中文，需要先抽 i18n 资源 |

## 不做（明确排除）

- **上传/云端转码**：产品定位就是「文件不出本机」，这是与在线转换站的核心差异。
- **DRM / 加密内容处理**：合规红线。
- **屏幕录制、剪辑、压制预设分享**：不在「格式转换」的问题域里。
